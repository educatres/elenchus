# AGENTS.md — elenchus 專案 Codex 實作指引

## 專案使命

建立部署在 GitHub Pages 的純前端蘇格拉底式 AI 學習系統。學生上傳教材並使用自己的 API Key，AI 只引導提問，不直接代答；系統在本機儲存教材、對話與形成性評量，教師可匯入報告覆核。

## 唯一權威規格

請先完整閱讀本 Repository 根目錄的 `DEVELOPMENT_SPEC.md`，依 0、5、7–12、16–18、21 章優先實作。任何矛盾以 `DEVELOPMENT_SPEC.md` 為準；如規格有工程上不可行之處，明確在 PR／交付說明中列出，不可默默改變功能。

## 永遠遵守

1. 靜態部署，不引入必備後端、雲端資料庫、登入服務。
2. API Key 僅當次執行記憶體使用，不持久化，不出現在 logs/export/URL。
3. `localStorage` 僅存輕量偏好，IndexedDB/Dexie 存教材、chunks、messages、reports。
4. PDF 文字引用必須對應真實資料與頁碼；不得虛構來源。
5. 學生模式優先問問題，採 L0–L4 Scaffolding，不能交出完整答案或完整作業。
6. 評量逐項有學生訊息證據，缺乏證據標 `not_assessed`；分數由前端確定性計算。
7. 角色切換不等於身分驗證；教師輸入／匯出亦不具有防竄改保證。
8. 所有使用者輸入／教材／模型輸出均為不可信資料，安全渲染、Zod 檢查。
9. 沒有可信 Provider 時必須明確顯示 Demo 或連線失敗；不能用假資料冒充真實結果。
10. 維持繁體中文 UI，桌面與手機均可用，保留實際進度與錯誤狀態。

## 開發節奏

- 依 Phase 0 → Phase 1 → Phase 2 → Phase 3 完成可驗證的垂直切片。
- 每次完成一個 Phase 需執行 typecheck / lint / test / build，更新 README 功能現況。
- 有 UI 更動要做 E2E 或至少記錄可重現的手動驗收步驟。
- 優先用簡單、容易測試的模組化設計，不因抽象化而阻塞 MVP。

## 終止條件

學生可匯入 PDF/TXT/MD、提供可用 Key、得到非代答的教材引導、恢復對話、完成獨立總結與遷移題、產生證據式報告，教師可匯入、覆核、匯出；網站可在 GitHub Pages `/elenchus/` 子路徑正常使用。

## 交付時回答格式

- 已完成項目與對應 AC 編號
- 執行的測試及結果
- 尚未完成／風險／假設（尤其 CORS 與 AI 非代答限制）
- 部署與操作說明
